# 零基础代码阅读指南

## 先认识这一版

项目全部8个Python文件已逐行添加以 `# 学习：` 开头的中文注释。通常先读注释，再看它下面紧邻的代码。空行用于分段；原有多行说明文字和页面字符串保持原样，不向字符串内部插入注释，以免改变实际数据。测试替身只改变模拟状态，不能当作真实设备控制接口。

本轮注释覆盖2124行非空代码行，包含独立主程序内重复合并的代码。运行程序、通信模块、模拟和测试的Python语法结构与上一提交一致；生成工具另外改为保留源文件注释，生成后的主程序逻辑仍与原版一致。具体核验见 `reports/comment_validation.json`。

## 建议阅读顺序

1. 先看 `docs/研究记录.md`，理解A–G坐标、最终路线和固定姿态。
2. 看 `simulate_ag.py` 的POINTS、build_plan和sample，先理解“一个动作列表怎样按时间展开”。它仅离线计算。
3. 看 `ag_trial.py` 的main，理解参数、只读检查、RUN/RECOVER启动确认和程序出口。
4. 看execute中的route列表及for循环，理解每段动作连续衔接。
5. 看Trial.robot与Trial.cylinder，理解“发指令、等反馈、确认到位、停顿1秒”。
6. 看Trial.tick，理解运动与停顿期间持续做哪些状态检查。
7. 最后看mcea_read.py、mcea_direction_test.py，学习串口字节、寄存器和CRC。

`ag_run.py`把以上相关定义合并成一个文件，适合单文件使用。因为按依赖顺序排列，它最前面是电缸通信，实际任务入口main在文件靠后位置；不必从第一页开始机械地背诵。VS Code中可搜索 `def main`、`def execute`、`def robot` 或 `route =` 定位。

## 常见语法

| 代码写法 | 简单理解 | 本项目例子 |
|---|---|---|
| `# ...` | 注释，Python执行时忽略 | `# 学习：...` |
| `name = value` | 将值保存到变量name | `POSITION_TOL = 0.0005` |
| `a == b` | 比较是否相等，结果为真/假 | `state['homing'] == 1` |
| `True / False / None` | 是/否/暂时没有值 | `recovery = False` |
| `[]` | 有顺序的列表，或取出其中一项 | `route[0]`是第一项 |
| `{key: value}` | 用名字索引的数据字典 | `report['success']` |
| `x[:3]` | 取前3项 | TCP的XYZ |
| `x[3:]` | 从第4项取到末尾 | TCP旋转向量Rx/Ry/Rz |
| `x[:]` | 复制整个列表 | 保存姿态副本，避免共用列表被修改 |
| `def name(...):` | 定义一段可调用的工作 | `def dwell(self):` |
| `return value` | 返回结果并结束当前函数 | `return result` |
| `class / self` | 把相关数据和方法组成对象；self是当前对象 | Trial保存本轮设备和状态 |
| `if / elif / else` | 条件选择分支 | 判断就绪或需要恢复 |
| `for` | 按顺序处理每一个元素 | 遍历route里的全部动作 |
| `while` | 条件成立时重复检查 | 等待到位或超时 |
| `break / continue` | 退出当前循环/跳到下一轮 | 到位退出等待；无效报文继续找 |
| `try / except / finally` | 尝试操作/处理错误/最后清理 | 动作失败后停止并关闭连接 |
| `raise` | 报告异常并打断正常流程 | 报警时不执行下一段 |
| `with` | 限定资源或测试替换的作用范围 | 网络连接与模拟函数替换 |
| `import` | 使用其他模块已提供的功能 | json、math、serial |
| `and / or / not` | 同时满足/任一满足/取反 | 多个状态条件组合 |
| `& / << / ^ / >>` | 按位与/左移/异或/右移 | 提取状态位和计算CRC |

冒号 `:` 后缩进的代码属于该条件、循环、函数或类。缩进决定代码归属，修改注释不需要改动缩进。

## 必须分清的单位

| 数据 | 程序单位 | 换算 |
|---|---|---|
| POINTS实测XYZ | mm | -337.9 mm对应-0.3379 m |
| 机械臂moveL目标前三项 | m | mm除以1000 |
| moveL参数v | m/s | 0.03 m/s=30 mm/s |
| moveL参数a | m/s² | 0.001 m/s²=1 mm/s² |
| Rx/Ry/Rz | rad旋转向量 | 不是欧拉角，也不是J6关节角 |
| 电缸目标与位置寄存器 | 0.01 mm | 4800=48 mm，1300=13 mm |
| 电缸扩展速度寄存器 | 0.01 mm/s | 100=1 mm/s |
| 电缸位置容差 | 5原始值 | 0.05 mm |
| 机械臂位置容差 | 0.0005 m | 0.5 mm |

`0x1600`是十六进制写法，等于十进制5632。程序里的5632与文档0x1600指同一个寄存器地址。

## 用一次电缸动作理解完整流程

`trial.cylinder(48)`表示去绝对位置48 mm：

1. 把48乘100，转换为寄存器目标4800。
2. 读取起始状态，确认无报警、已使能、已回零且目标合法。
3. 写两帧完整参数：先控制字0x20准备，再0x21触发。两帧都是同一目标、1 mm/s、加速度1%，不沿用旧目标。
4. 循环读报警、实际位置和运动/到位状态；同时调用tick监控机器人保持不动。
5. 位置误差≤0.05 mm、运动位为0、到位位为1，连续3次成立后才认为完成。
6. 停顿1秒，等待期间继续检查；然后route循环才进入下一动作。

机械臂robot方法同样采用“下发异步命令→持续读反馈→核对到位与静止→监控停顿”。异步表示发送后函数不会在控制接口内部一直阻塞等待，本程序用自己的循环检查过程，整套任务仍按顺序串行执行。

## 启动入口与离线学习

`if __name__ == '__main__':`表示“直接启动这个文件时才执行下面入口”。导入文件只定义函数和类，不会自动连接设备。注意：`ag_run.py`直接启动且无参数时默认选择实际运行入口；学习时明确使用离线参数：

```powershell
python ag_run.py --preview
python simulate_ag.py --out-dir simulation_output
python run_offline_tests.py
```

`--check`是设备只读检查，仍需连接设备；`--preview`与simulate_ag.py不连接设备。实际连续任务仍需一次RUN或RECOVER确认，动作之间没有GO等待。

`mcea_direction_test.py`是复用来源兼历史独立方向测试，保留它自己的START/GO等确认；这不是A–G连续主程序的执行入口。学习本次完整流程请以ag_run.py/ag_trial.py为主。

## 注释如何随重新生成保留

修改模块代码后，可运行：

```powershell
python tools/build_single_file.py
python run_offline_tests.py
```

生成工具现在直接保留已选源代码和中文注释，省略已合并的本地模块导入，再组合为ag_run.py。重新生成不连接设备，也不会抹掉已有逐行注释。新增代码仍需补充对应注释。

## 继续学习时如何核对理解

先尝试回答：为什么XYZ要除1000？为什么电缸位置要乘100？为什么动作完成后还要检查实际位置？为什么暂停后下发新目标0，而不只清暂停位？为什么普通运行保持固定姿态，恢复时才允许主动改变姿态？答案都能在相应代码注释与研究记录中找到。
