# A–G连续运行程序

主程序：`ag_run.py`。在VS Code中运行，或在文件所在文件夹执行：

```powershell
python ag_run.py
```

设备连接正常后，输入一次 `RUN` 并回车，连续完成整套动作。已删除所有逐段 `GO` 确认及 `--step` 模式。每段到位后仍停顿1秒，随后自动进入下一段。只运行一轮，最终机械臂返回A、电缸返回0 mm，随后退出；不会无限循环。Ctrl+C请求软件停止。

只读查询：`python ag_run.py --check`。离线计划：`python ag_run.py --preview`。导入本文件不会连接设备。模块版 `ag_trial.py` 使用 `--run` 启动连续运行，默认仍为只读查询。

## 路线与参数

路线：当前位置→A→B→电缸48 mm→C→电缸13 mm→A→D→E→电缸48 mm→F→G→电缸0 mm→A。

- 机械臂：192.168.21.5；任务平移30 mm/s，加速度1 mm/s²。
- 电缸：COM4，115200、8N1、站号1；速度1 mm/s，加减速度1%。
- 每段到位后停顿1秒。保持实测A–G坐标和既有动作顺序。
- 姿态固定为2026-11-12 13:10:55（北京时间）读取的底座坐标系旋转向量，Rx=1.4747881408617243、Ry=-0.6236196873562871、Rz=0.6049084354198352 rad；不锁定J6，不重新捕获或归零姿态。

依赖：`pyserial==3.5`、`ur_rtde==1.6.5`。单文件已包含电缸通信逻辑，无需其他本地Python模块。

## 中断后的恢复

重新启动时，若检测到可恢复的电缸软件暂停、非零位置或姿态偏差，程序提示输入一次 `RECOVER`。确认后会连续执行以下过程，无需再输入RUN或GO：

1. 机械臂保持当前XYZ和姿态，电缸以1 mm/s回到已标定的0 mm。使用全新的0 mm定位参数解除已识别的0x28软件暂停，不重发旧目标。
2. 保持当前XYZ，将末端恢复到上述记录的固定姿态。此准备段保持原有moveL参数v=0.001 m/s、a=0.001 m/s²。
3. 电缸保持0 mm，机械臂回A，随后从A→B开始连续完成一轮新流程。

RECOVER确认包括完整恢复过程及后续一轮动作。不会续跑中断的旧步骤。急停、保护停止、报警、失能、未回零、未知控制模式或其他运行中的机器人程序仍会阻止执行；恢复不自动清除这些状态。回0是回到已标定位置，不执行寻端回零。

## 状态检查与日志

原有通信、报警、急停、控制器目标限位、姿态及到位检查保持原逻辑。全路径采样保持关闭，速度仅记录，不恢复此前额外的瞬时速度中断阈值。任何阶段失败都会中断后续流程并尝试软件停止，断线不自动重试或强制回A。软件停止不能替代现场急停。

运行日志位于主程序同目录的 `logs` 文件夹。
